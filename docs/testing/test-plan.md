| 项目 | 内容 |
| --- | --- |
| 被测分支 | `lab-1`（`b1355e9e`） |
| 测试分支 | `test/lab-1-round2` |
| 被测功能 | `src/kernel/main.c`：双核启动、4.1 并行加法、printf、自旋锁 |
| 测试代码 | `tests/`（10 个用例 + 一键运行） |
| 测试环境 | VMware Workstation 17.6.4 / Ubuntu 24.04.3 LTS x86_64 |
| 工具链 | `riscv64-linux-gnu-gcc 13.3.0`、`qemu-system-riscv64 8.2.2`、`gdb-multiarch 15.1` |

## 1. 测试目标

1. 验证 `main.c` 的双核启动分支：两个 hart 都能进入 `main` 并输出。
2. 验证 4.1 并行加法：加锁时 `sum` 必须达到 2000000；去锁时能复现丢更新。
3. 验证 `printf` 的正确性：五个格式符、数值边界、特殊格式符。
4. 验证自旋锁：互斥、竞争、错误用法（重复加锁、未持有释放）。
5. 用测试代码把上述行为固定下来，作为后续 lab 的回归基线。

## 2. 被测功能与测试策略

| 功能点 | 代码位置 | 测试方法 |
| --- | --- | --- |
| 双核启动 | `main.c` 的 `cpuid` 分支 | `-smp 2` / `-smp 1` 对照 |
| 4.1 并行加法 | `main.c` 的 `sum_lk` 临界区 | 加锁 / 去锁对照，重复运行 |
| printf 格式符 | `lib/print.c` | 等价类划分 |
| printf 数值/字符串 | `lib/print.c` | 边界值分析 |
| 输出互斥 | `print_lk` | 去锁后观察 A/B 交错 |
| 自旋锁 | `lock/spinlock.c` | 竞争压力 + 错误用法注入 |

## 3. 等价类与边界值设计

### 3.1 printf 格式符（等价类）

| 类别 | 代表输入 | 预期输出 |
| --- | --- | --- |
| 有符号十进制 | `%d`, `-123` | `-123` |
| 十六进制（64 位、带 0x） | `%x`, `0x123456789abcdef0` | `0x123456789abcdef0` |
| 十六进制（32 位、不带 0x） | `%p`, `42` | `2a` |
| 字符 | `%c`, `'A'` | `A` |
| 字符串 | `%s`, `"ok"` | `ok` |
| 转义百分号 | `%%` | `%` |
| 未知格式符 | `%q` | 不崩溃（当前实现静默丢弃） |

### 3.2 printf 边界值

| 类别 | 取值 | 预期 |
| --- | --- | --- |
| 有符号最小值 | `INT_MIN` | `-2147483648` |
| 有符号最大值 | `INT_MAX` | `2147483647` |
| 零 | `0` | `0` |
| 负一 | `-1` | `-1` |
| 64 位无符号最大值 | `0xffffffffffffffff` | `0xffffffffffffffff` |
| 空字符串 | `""` | 空 |
| 空指针 | `NULL` | 空，且不崩溃 |
| 长字符串 | 200 个字符 | 完整输出 |

### 3.3 自旋锁

| 类别 | 场景 | 预期 |
| --- | --- | --- |
| 正常互斥 | 两核各 100 万次，整段加锁 | 最大值 2000000 |
| 细粒度竞争 | 两核各 20 万次，每次加锁 | 最大值 400000 |
| 去锁对照 | 去掉 `sum_lk` | 最大值明显小于 2000000 |
| 输出互斥 | 去掉 `print_lk`，两核打印长串 | 出现 A/B 交错 |
| 重复加锁 | 同一 CPU 连续 acquire 两次 | panic |
| 未持有释放 | 直接 release | panic |

## 4. 测试代码组织

```
tests/
├── run_tests.sh            一键运行全部用例
├── show_case.sh            单独展示一个用例（用于截图）
├── screenshot_cases.sh     自动逐用例截图
├── cases/<用例>/
│   ├── case.conf           运行参数与说明
│   ├── check.sh            判定规则
│   ├── prepare.sh          可选：注入测试代码
│   └── files/              可选：覆盖源文件
└── results/                运行日志（不入库）
```

每个用例都在**工程副本**上修改和编译，不污染 `src/`。

## 5. 通过标准

- 用例的 `check.sh` 返回 0 记为 PASS，否则 FAIL；
- `07_printf_percent` 预期 FAIL，因为当前 `printf` 不支持 `%%`（已登记 BUG-5）；
- 其余 9 个用例必须 PASS。

## 6. 风险与假设
