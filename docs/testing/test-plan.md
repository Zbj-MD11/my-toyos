# lab-1 测试计划

| 项目 | 内容 |
| --- | --- |
| 被测分支 | `lab-1` |
| 测试分支 | `test/lab-1-round1` |
| 测试类型 | 功能验收 + 边界/故障注入 + 回归 |
| 测试环境 | VMware Workstation 17.6.4；Ubuntu 24.04.3 LTS x86_64 |
| 工具链 | `riscv64-linux-gnu-gcc 13.3.0`、`qemu-system-riscv64 8.2.2`、`gdb-multiarch 15.1` |
| 启动参数 | `-machine virt -bios none -m 128M -smp 2 -nographic` |

## 1. 测试目标

1. 验证 lab-1 的核心目标：双核启动、进入 `main`、串口输出两行启动信息。
2. 验证 `printf` 与自旋锁在双核下的正确性（`sum = 2000000`）。
3. 通过边界与故障注入，找出当前实现中会影响后续 lab 或评测环境的缺陷。
4. 为后续 lab 建立可复用的回归基线。

## 2. 测试范围

- **A 功能验收**：编译、双核启动、4.1 加锁/去锁、4.2 并行输出、printf 格式、单核对照、稳定性、GDB、最终回归。
- **B 边界与故障注入**：多核越界、内存边界、默认 bios、关闭 PMP、printf 边界、panic/assert 路径、长输出、Makefile 行为。
- **C 修复与交付**：缺陷修复、回归、文档、提交。

## 3. 通过标准

| 级别 | 标准 |
| --- | --- |
| 阻断 | 干净编译通过；`-smp 2` 下两行启动信息齐全；无 panic/卡死 |
| 功能 | `sum = 2000000`；单核只输出 `cpu 0`；printf 五个格式符符合约定 |
| 稳定 | 连续 10 次运行全部通过 |
| 边界 | 记录实际行为；与预期不符即登记为缺陷，再评估是否修复 |

## 4. 风险与假设

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| QEMU 版本差异 | 课程环境 QEMU 较旧；本机 8.2.2 对 PMP 更严格 | 修复后需在旧版本上保持兼容（PMP 配置无害） |
| 评测环境未知 | 若评测使用默认 `-bios`（OpenSBI），入口地址与特权级不同 | 本计划记录该场景的实际行为 |
| 共享文件夹 | VMware 共享目录下 git/编译可能有权限或性能问题 | 必要时 clone 到 `~/` 再测 |
