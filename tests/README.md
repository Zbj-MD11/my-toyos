# Lab4 测试说明

我测试了第一个用户进程的创建、用户地址空间、系统调用、用户态时钟与串口中断、异常保护，以及上下文和寄存器的保存恢复。2026-11-27 的全量执行批次为 `20261127-105726`，24 条用例全部通过。

## 文件与执行方式

- `run_tests.py`：24 条用例的定义、用户程序生成、隔离构建、QEMU 运行及结果判定。
- `probe.c`：初始化、页表权限、用户态 Trap 和上下文切换的检查探针。
- `results/20261127-105726/`：本批串口日志、编译日志、汇总和机器判定。
- `../docs/testing/test-report.md`：按测试模板填写的完整报告。
- `../docs/testing/images/20261127-105726/`：24 张用例日志图和 1 张汇总图。

将提交目录中的 tests 和 docs 合入 Lab4 仓库根目录。运行测试驱动需要该仓库已有的 src、Makefile、common.mk 和 kernel.ld。在能够正常启动该内核的 Linux 环境中，从仓库根目录执行：

```bash
# 查看全部用例
python3 tests/run_tests.py --list

# 执行全部用例
python3 tests/run_tests.py

# 单独执行一条
python3 tests/run_tests.py --case 05_user_timer
```

驱动需要 Python 3、GNU Make、RISC-V GNU 工具链、xxd 和 qemu-system-riscv64，自身不依赖 Pillow。本机同步入口、环境适配和截图生成脚本不随本次材料提交，现有图片已经保留在报告目录中。

## 判定与证据

每条用例复制源码后独立编译、独立启动 QEMU，测试替换和探针只写入该条测试构建。构建失败、入口地址不正确、QEMU 提前退出或所需证据缺失均判失败；用户程序不能超过一页。

每条运行上限为 5 秒，由驱动结束 QEMU。正常用例检查精确的 hello 输出次数，不能出现 panic；非法系统调用和自然异常必须匹配指定诊断与 panic，页故障还检查 scause 和故障地址。预期 panic 不作为内核缺陷。

运行结果按批次保存。status.json 是各条判定，summary.txt 是汇总，*.build.log 是编译日志，其余 *.log 是串口输出和判定。图片来自本批真实串口日志，属于日志渲染图片。报告中所有证据链接都指向本批固定目录。

## 结论范围

01 保留原始用户程序和内核执行路径；其余用例在独立构建中替换用户程序或加入探针。23 检查 sp、ra、gp、tp、t0～t6、s0～s11、a1～a7，以及 a0 的返回值；24 检查 swtch 的 ra、sp、s0～s11 往返恢复。

双核用例验证两核启动、两次 hello 输出以及用户时钟路径，不代表验证了跨核调度或精确的 tick 倍率。时钟用例验证用户态中断入口、ticks 增长和保存的返回 PC，不据此推断长时间用户计算的正确性。本次没有长期压力或性能测量。
